# Сайт для проведения контрольных работ

Flask-приложение с двумя режимами: **студент** и **преподаватель**.

## Что добавлено

- студент обязательно вводит **ФИО** и **группу**;
- студенту случайно назначается один из вариантов;
- вопросы и ответы загружаются **двумя отдельными DOCX-файлами**;
- тестовый вопрос ограничен 40 секундами, открытый — 120 секундами;
- ответы проверяются автоматически;
- результат сохраняется в базе данных;
- преподаватель видит таблицу: ФИО, группа, работа, вариант, баллы, процент, оценка, дата/время;
- результаты можно скачать в CSV;
- на Render результаты хранятся в **PostgreSQL** и не пропадают при перезапуске или новой публикации.

## Формат DOCX с вопросами

Каждый вариант начинается отдельной строкой. Вопросы нумеруются. Для типа вопроса используйте `[ТЕСТ]` или `[ОТКРЫТЫЙ]`.

```text
ВАРИАНТ 1
1. [ТЕСТ] Столица Франции?
A) Париж
B) Лондон
C) Рим

2. [ОТКРЫТЫЙ] Сколько будет 2 + 2?

ВАРИАНТ 2
1. [ТЕСТ] Столица Италии?
A) Рим
B) Париж
```

Если у вопроса есть строки `A)`, `B)` и т. д., он также автоматически распознаётся как тестовый.

## Формат отдельного DOCX с ответами

```text
ВАРИАНТ 1
1. A
2. 4 | четыре

ВАРИАНТ 2
1. A
```

Символ `|` разделяет несколько допустимых открытых ответов. Регистр, лишние пробелы и различие `е/ё` при проверке игнорируются.

## Локальный запуск

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

Создайте `.env` по примеру `.env.example` или задайте переменные в терминале:

```bash
export SECRET_KEY='длинная-случайная-строка'
export TEACHER_PASSWORD='ваш-пароль'
export DATABASE_URL='sqlite:///control_work.db'
python app.py
```

На Windows PowerShell вместо `export` используйте `$env:ИМЯ='значение'`.

Откройте `http://127.0.0.1:5000`.

## Как добавить обновление в уже существующий GitHub-репозиторий

### Вариант 1 — через сайт GitHub

1. Распакуйте архив проекта.
2. Откройте свой существующий репозиторий на GitHub.
3. Нажмите **Add file → Upload files**.
4. Перетащите **содержимое** папки `control-work-site-v2`, а не ZIP-файл.
5. Разрешите замену одноимённых файлов (`app.py`, `requirements.txt`, шаблоны и т. д.).
6. Внизу напишите сообщение, например `Add student data and persistent results`.
7. Нажмите **Commit changes**.

Важно: браузерная загрузка не удалит старые файлы, которых нет в новом архиве. Если в старом проекте были несовместимые шаблоны, перед загрузкой удалите старые папки `templates` и `static`, затем загрузите новые.

### Вариант 2 — через Git

В распакованной папке проекта:

```bash
git init
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git fetch origin
git add .
git commit -m "Add student data and persistent results"
git push -u origin main
```

Если репозиторий уже клонирован, просто замените в нём файлы файлами из архива и выполните:

```bash
git add .
git commit -m "Add student data and persistent results"
git push
```

## Как включить постоянное хранение на Render

Обычный SQLite-файл на бесплатном веб-сервисе Render может исчезнуть при перезапуске или новом развёртывании. Поэтому эта версия поддерживает Render Postgres.

### Для уже созданного Web Service

1. В Render нажмите **New → Postgres**.
2. Создайте базу, например `control-work-db`, в том же регионе, что и Web Service.
3. Откройте Web Service → **Environment**.
4. Добавьте переменную `DATABASE_URL` и привяжите её к **Internal Database URL** созданной PostgreSQL-базы.
5. Проверьте переменные:
   - `TEACHER_PASSWORD` — пароль преподавателя;
   - `SECRET_KEY` — длинная случайная строка;
   - `DATABASE_URL` — адрес PostgreSQL.
6. Build Command: `pip install -r requirements.txt`.
7. Start Command: `gunicorn app:app`.
8. Нажмите **Save Changes**, затем **Manual Deploy → Deploy latest commit**.

При первом запуске таблицы создаются автоматически. После этого результаты будут храниться в PostgreSQL и сохраняться между перезапусками.

### Для нового проекта через Blueprint

В репозитории уже есть `render.yaml`:

1. Render → **New → Blueprint**.
2. Подключите GitHub-репозиторий.
3. Подтвердите создание Web Service и PostgreSQL.
4. Когда Render запросит `TEACHER_PASSWORD`, введите пароль преподавателя.
5. После публикации откройте выданный адрес `*.onrender.com`.

## Работа преподавателя

1. Откройте **Преподаватель** и введите пароль из `TEACHER_PASSWORD`.
2. Загрузите DOCX с вопросами и укажите название работы.
3. У созданной работы отдельно загрузите DOCX с ответами.
4. Нажмите **Опубликовать**.
5. После прохождения студентами результаты появятся в таблице.

## Проверка проекта

```bash
pytest
```

Тесты проверяют распознавание DOCX, загрузку вопросов и ответов, назначение варианта, прохождение работы, автоматическую оценку и сохранение ФИО/группы.

## Безопасность

Не записывайте настоящий пароль преподавателя и `SECRET_KEY` в код, `.env` или публичный GitHub-репозиторий. Храните их только в Environment Variables на Render. Если ранее пароль был опубликован в репозитории, замените его.
